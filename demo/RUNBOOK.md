# 实机演示 Runbook

**目标**：让观众在 3 分钟内看到 —— 同一个文件，普通下载要等好几分钟，
换这个工具几十秒就完事，而且结果一模一样。

**核心信息**（一句话）：*并发不是魔法，它只是把被单连接限速浪费掉的带宽用起来。*

---

## 一、演示前 5 分钟检查

```bash
cd <仓库目录>

# 1. Python 可用
python --version                      # 需要 3.8+

# 2. 【最重要】预检：先确认素材能演出加速效果
python demo/compare_download.py --preflight --no-tls-verify

# 3. 用预检推荐的参数，完整跑一遍确认耗时
python demo/compare_download.py --no-tls-verify --limit-mb 2
```

### 为什么必须预检：同一素材的提速波动极大

**2026-10-06 本机实测**（完全相同的配置：4 MiB 样本、`-c 1`、8 线程）：

| 素材 | 第一次 | 第二次 |
|---|---|---|
| `cli/cli` windows zip | **0.90x** | **2.06x** |
| `flowwatch` win64-exe | 2.31x | 2.45x |

**看第一行**：同一个素材、同样参数，两次跑出 0.90x 和 2.06x，差 2.3 倍。

我一开始以为这是「cli/cli 的 CDN 对同 IP 做了聚合限速」的素材特性，
换了有效样本重测后翻案了 —— 那就是**网络波动**，不是素材问题。

> **两条教训**：
> 1. 两个数据点不足以支撑因果结论（我就是这么误判的）。
> 2. 素材名气与提速无关，**能不能演出效果主要看当时的链路状况**。
>
> 所以演示前**必须**跑一次预检 —— 不是选素材，是确认"今天这条线能不能演"。

`--preflight` 会用 4 MiB 样本（保证切出多片）测几个候选素材，
直接告诉你今天哪个能看，并给出可复制的命令。

### 一个会骗人的陷阱：样本太小

`--preflight` 曾用 1 MiB 样本，测出 **0.70x** —— 假的。
因为 1 MiB 配 1 MiB 分片只有 **1 片 = 单连接**，并发根本没发生。

所以预检现在强制样本 ≥ 4 MiB（`ensure_parallel_sample()`），
并把这个不变量写进了测试。**自己调样本时务必让分片数 ≥ 4**。

### 按预检结果选 `--limit-mb`

| 预检看到的单连接速度 | 建议 |
|---|---|
| 很快（> 1 MB/s） | `--limit-mb 8` 以上，否则并发优势看不出来 |
| 中等（200~500 KB/s） | `--limit-mb 4`（默认，约 2.5 分钟） |
| 很慢（< 100 KB/s） | `--limit-mb 2`，并做好"现场等一分钟"的心理准备 |

> 演示前**务必**跑一次完整流程。只跑 `--help` 不算 —— 真实下载涉及的
> TLS、CDN、限流问题，只有真跑才会暴露。

## 二、现场流程（四幕）

### 幕 1 · 开场（20 秒，不敲命令）

> "从 GitHub 下一个几百 MB 的文件，单连接经常只有几十 KB/s，一等就是几小时。
> 这不是网速问题，是服务端对**单个连接**限速。
> 这个工具用多连接把同一份文件同时拉下来。"

可以先展示这一行（`--list-assets`），让观众看到"它知道文件有哪些"：

```bash
curl -LO https://github.com/joker1point/gh-fast-download/releases/latest/download/fastdl.py
python fastdl.py --gh-release cli/cli --tag v2.102.0 --list-assets
```

> 顺便强调：**没装 gh、不用 token**，公开仓库直接可用。

### 幕 2 · 一键对比（主戏）

```bash
python demo/compare_download.py --no-tls-verify --limit-mb 4
```

脚本会依次做：
1. 打印环境（`gh CLI: 未安装`、`GITHUB_TOKEN: 未设置`）→ 立住"新用户"人设
2. 走新用户两步：下载脚本、列资产
3. **对照 A**：单连接下载同样字节数 ← 这一幕观众要等一会儿，就是重点
4. **对照 B**：多线程下载同样字节数
5. 打印对照表 + sha256 一致性核对

**等待时的解说**（对照 A 那段空窗不要冷场）：

> "现在它正在用**一个连接**下 —— 和浏览器另存为、`curl -L` 完全一样。
> 注意看速度…… 好，现在换这个工具，**同样的字节数**，看它多久。"

### 幕 3 · 收尾（念结果）

指着最后那张表：

> "同样 4 MiB，单连接用了 X 秒，多线程用了 Y 秒。
> 而且注意最后一行 —— **两个文件 sha256 完全一致**。
> 并发分片最大的风险是拼错数据，所以每次都会校验。"

### 幕 4 · 补一刀（可选，20 秒）

展示自动校验官方 digest 这件事 —— 这是很多下载工具不做的：

```bash
python fastdl.py --gh-release cli/cli --tag v2.102.0 --asset gh_2.102.0_checksums.txt
```

输出里会有 `sha256 ... 校验通过 ✓`，而 digest 是 GitHub 官方提供的。

## 三、可能被问到的问题

**Q：这不就是 aria2 吗？**
> 思路一样，aria2 功能更强。但它要额外安装，这个是零依赖单文件，
> `python fastdl.py <链接>` 就能跑，适合"临时下一个东西"。
> 已经有 aria2 的话用它也行，`-x16` 是等价的。

**Q：为什么不用加速镜像？**
> 实测过，全挂了：ghfast.top 403、ghproxy.net 403、gh-proxy.com 404、
> 另外两个直接不通。镜像生态变动太快，不如直接走并发。
> 文档里有这张实测表。

**Q：走代理会不会更快？**
> 实测更慢，慢 3 倍。所以这个工具默认主动绕过系统代理。

**Q：会不会被 CDN 限流？**
> 会。对同一个 IP 高频发 Range 请求会被限流，表现为"并发反而更慢"。
> 文档里建议了应对：调低 `-t`、加大分片，或者干脆说明这种情况不适合并发。
> **我们不承诺任何固定倍数**——收益取决于链路是否被限速。

**Q：安全吗？**
> 经过一次独立安全审查，发现并修掉了一个真实缺陷：
> 调用 GitHub API 时曾经**无条件**关掉 TLS 校验，同时又发送 token，
> 存在凭据被中间人窃取的风险。现在默认强制校验，且"关校验 + 带凭据"
> 会主动告警。release 附件里带了 49 个离线测试，可以自己下载复验。

**Q：为什么不做个 exe 双击运行？**
> 实测做过：28 KB 的脚本打包后 9.6 MB，而且包完就**不能审计**了。
> 用户能读 28 KB 的 Python，读不了打包的二进制 ——
> 那等于把我们刚建立的可验证性扔掉。装 Python 一条
> `winget install Python.Python.3.12` 就够了。

**Q：提速到底多少倍？**
> 取决于链路。本机实测 4~7 倍，最好的情况到过 11 倍。
> 但只要单连接没被限速，提升就会很小 —— 这我们也会如实说。

## 四、翻车了怎么办

| 状况 | 处理 |
|---|---|
| 网络太慢，观众等太久 | 现场 `Ctrl-C` 中断，改 `--limit-mb 2` 重跑。**分片会保留，续传很快** |
| 下载失败报错 | 大概率是网络抖动。重跑同一条命令即可续传，不用从头下 |
| 并发没提速（<1.3x） | 别硬圆。直接说："这条链路单连接已经不被限速了，所以并发没优势 —— 这个工具只在被限速时有价值。" **诚实比好看重要** |
| Windows 报证书错误 | 加 `--no-tls-verify`（schannel 吊销检查问题的绕法） |
| 时间实在不够 | 只演幕 4（自动校验），比"又快又安全"更好讲 |
| 现场发现提速只有 1x | 立刻换素材重跑（`--repo/--tag/--asset`）。这也是预检要提前做的原因 |

> **最好的底牌**：这个工具的价值主张本身就包含"什么时候它没用"。
> 遇到不利结果时坦率承认，反而比硬凑数字更让人信。
